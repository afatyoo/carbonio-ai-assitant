# Carbonio AI Assistant v2.3.0

**Release class:** Contextual workflow and administration feature release

**Release date:** 2026-08-09

**License:** MIT

**Support status:** Independent community addon. Not developed, certified, endorsed, or supported by Zextras.

## Executive summary

Version 2.3.0 adds an exact-target `Ask AI` workflow to Carbonio Mail. A localized action in a
message or conversation menu opens a fresh full assistant conversation with an ID-only context
reference and relevant prompts. No subject, participant, preview, body, or attachment content is
placed in the URL or browser storage. The gateway retrieves the exact selected object through the
authenticated Carbonio session only after the user sends a question.

This release also separates user and administrator configuration. Provider credentials, endpoint,
model, and fallback selection remain in Webmail Settings. Global OpenRouter ZDR policy, gateway
health, emergency write controls, metrics, and administrator-visible audit activity are available
at `https://<carbonio-host>:6071/carbonioAdmin/ai-assistant`. ZDR remains enabled by default.
Turning it off requires explicit provider data-retention risk acceptance, and the gateway records
the acceptance time in its protected runtime configuration.

Administrator audit activity identifies users by Carbonio account email instead of presenting only
an internal UUID. The immutable UUID remains available as a technical hover reference. Existing
rows are backfilled through the authenticated Carbonio Admin SOAP session, while new rows capture
the already-authenticated account name when the tool runs.

The port 6071 page also provides Organization Knowledge RAG. Administrators can upload bounded
company policies, SOPs, and internal guidance. The content is encrypted and indexed under a
dedicated non-mailbox owner, then retrieved read-only alongside each user's private sources with
document citations. Safe text formats are accepted directly. PDF and Office extraction fails
closed until malware scanning, a no-network sandbox, and a bounded extractor are configured.

The same administrator page now discovers eligible Carbonio mailbox accounts automatically and
presents explicit AI access and write-tool access checkboxes. Discovery uses the authenticated
Admin SOAP session, excludes internal service identities, and preserves immutable Carbonio account
IDs behind the UI. Saved choices are atomic server-side overrides and are effective immediately.
Environment allowlists remain the bootstrap defaults for accounts without an override.

Carbonio Mail does not currently expose a public extension point for message and conversation
menus, including in the official v1.41.1 source. This release therefore uses a narrow compatibility
bridge bound to known `data-testid` contracts. The bridge fails closed and leaves core Mail actions
untouched if it cannot prove the menu type and exact target ID.

The release does not weaken existing owner isolation or confirmation boundaries. Provider fallback
does not run after authentication, authorization, invalid-input, privacy-policy, or cancellation
failures. Undo requires a new exact preview and single-use confirmation. Private source retrieval
still performs live Carbonio access and revision revalidation before evidence reaches a provider.

## Risk acceptance

- This is a community addon. The operator owns support, provider contracts, privacy review,
  monitoring, backup custody, incident response, upgrade testing, and rollback.
- AI output and tool planning remain probabilistic. Users must review every write or destructive
  confirmation and verify recipients, targets, permissions, timezones, and permanent effects.
- Third-party providers can receive the minimized content required for an approved request.
- Fallback models must satisfy the same privacy and contractual policy as the primary model.
- Undo covers only explicitly mapped reversible actions and is not a transaction rollback.
- Optional PDF and office extraction expands the attack surface and must remain disabled until
  every scanner, sandbox, extractor, and resource limit is reviewed on the target server.
- Backup success does not prove a business recovery objective. Site operators must rehearse and
  measure restore time and authenticated application behavior.
- Files and Docs, Chats and rooms, unsupported Tasks mutations, high availability, and untested
  Carbonio versions remain outside the verified scope.
- The `Ask AI` menu compatibility bridge must be revalidated after Carbonio Mail UI upgrades.
  If its bounded DOM contract changes, the action can disappear while core Mail remains unaffected.
- Disabling ZDR can allow the selected provider endpoint to retain prompts, responses, and the
  minimized Carbonio data required by a request according to its own policy. The operator accepts
  responsibility for provider terms, retention, training, logging, residency, and deletion.
- Carbonio Admin Console v0.15.2 has no public addon registry. The dedicated page uses a managed
  Nginx include on port 6071 and leaves the official monolithic `shell.mjs` bundle unchanged.

## Complete closed-bug ledger

### BUG-001 - Provider changes could not be verified before user traffic
- **Symptom:** A saved endpoint or model failed only when a user opened chat.
- **Root cause:** Settings had no bounded server-side connection probe.
- **Resolution:** Added an administrator connection test using the saved effective configuration.
- **Regression/evidence:** Provider tests validate success, latency, active model, and safe failure.

### BUG-002 - Model availability failure stopped every request
- **Symptom:** A missing or temporarily unavailable primary model caused an immediate outage.
- **Root cause:** Completion supported only one configured model.
- **Resolution:** Added ordered fallback models for explicitly retryable availability failures.
- **Regression/evidence:** A simulated primary 404 selects the allowed fallback and exposes it.

### BUG-003 - Unsafe errors could trigger provider fallback
- **Symptom:** A broad retry policy could hide invalid credentials or privacy rejection.
- **Root cause:** Failure eligibility was not separated by status and error class.
- **Resolution:** Authentication, authorization, validation, privacy, and cancellation now fail closed.
- **Regression/evidence:** Provider regression asserts no fallback for every excluded class.

### BUG-004 - Active fallback model was invisible
- **Symptom:** Users could believe the configured primary answered when a fallback was active.
- **Root cause:** Streaming responses reported text only.
- **Resolution:** Added a provider runtime event and localized active-model status.
- **Regression/evidence:** Stream and plain-text UI contracts verify model visibility.

### BUG-005 - Operational health was fragmented
- **Symptom:** Operators needed multiple endpoints and journals to understand one incident.
- **Root cause:** No combined component matrix existed.
- **Resolution:** Added gateway, history, RAG, provider, and write-state health components.
- **Regression/evidence:** Health tests cover healthy, degraded, error, and disabled states.

### BUG-006 - Metrics lacked a monitoring format
- **Symptom:** Existing counters could not be scraped directly by Prometheus.
- **Root cause:** Metrics were exposed only as administrator JSON.
- **Resolution:** Added loopback Prometheus output protected by a separate bearer token.
- **Regression/evidence:** Formatter, authentication, token rotation, and smoke contracts pass.

### BUG-007 - Repeated provider failures lacked alert guidance
- **Symptom:** Provider and RAG failures could remain unnoticed until users reported them.
- **Root cause:** No deployable alert baseline existed.
- **Resolution:** Added scrape and alert examples for gateway, health, worker, queue, and provider.
- **Regression/evidence:** Hardening checks require the metrics route and protected configuration.

### BUG-008 - RAG sync reprocessed unchanged records
- **Symptom:** Every sync re-embedded the full source set.
- **Root cause:** Queue creation did not compare durable source revisions.
- **Resolution:** Sync now queues only new or changed ID and revision pairs.
- **Regression/evidence:** RAG contract verifies unchanged count and zero redundant upserts.

### BUG-009 - RAG deletion progress was not visible
- **Symptom:** Users could not distinguish changed, unchanged, and removed records.
- **Root cause:** Source state stored only aggregate document and chunk counts.
- **Resolution:** Added durable incremental sync statistics and localized Settings output.
- **Regression/evidence:** UI and RAG tests verify scanned, changed, unchanged, and deleted counts.

### BUG-010 - Worker liveness was inferred from queue depth
- **Symptom:** A dead worker with an empty queue appeared normal.
- **Root cause:** No durable worker heartbeat existed.
- **Resolution:** Added a runtime heartbeat with freshness evaluation and worker details.
- **Regression/evidence:** Operational health marks stale or failed worker state degraded.

### BUG-011 - Retrieval quality had no repeatable gate
- **Symptom:** Recall and no-answer behavior could regress without a measurable report.
- **Root cause:** Evaluation existed only as a written target.
- **Resolution:** Added a bounded owner-scoped evaluator for recall@8, no-answer precision, and p95.
- **Regression/evidence:** Evaluation tests cover passing, failing, bounds, and percentile behavior.

### BUG-012 - RAG sources were rendered as plain generated text
- **Symptom:** Users could not reliably open the evidence used by an answer.
- **Root cause:** The stream did not carry structured source metadata.
- **Resolution:** Added server-controlled source events and clickable safe source links.
- **Regression/evidence:** TypeScript and stream contracts reject unstructured source fields.

### BUG-013 - Binary documents had no safe expansion path
- **Symptom:** PDF and office content was permanently metadata-only even in reviewed environments.
- **Root cause:** No fail-closed scanner and sandbox interface existed.
- **Resolution:** Added optional extraction requiring scanner, sandbox wrapper, and extractor together.
- **Regression/evidence:** Missing configuration and suspicious content remain metadata-only.

### BUG-014 - Administrators lacked a persistent emergency write stop
- **Symptom:** Disabling writes required editing environment policy and restarting the service.
- **Root cause:** No constrained runtime safety state existed.
- **Resolution:** Added a persistent administrator control subordinate to environment policy.
- **Regression/evidence:** Tests prove environment disable cannot be overridden by runtime state.

### BUG-015 - Users lacked a single safety activity view
- **Symptom:** Recent tool risk, target reference, status, and request ID were scattered.
- **Root cause:** User audit data was not presented in Settings.
- **Resolution:** Added an owner-scoped Safety Center activity list.
- **Regression/evidence:** API and UI enforce account ownership and bounded activity counts.

### BUG-016 - Reversible folder moves had no Undo path
- **Symptom:** Move, archive, and restore errors required manual recovery.
- **Root cause:** Successful mutations did not persist a bounded inverse action.
- **Resolution:** Added time-limited exact previous-folder inverses for move, archive, and restore.
- **Regression/evidence:** Undo tests cover ownership, expiry, single use, and inverse mapping.

### BUG-017 - Undo could have trusted stale browser destinations
- **Symptom:** A move inverse could return a message to an invented folder.
- **Root cause:** Previous folder state was not captured from Carbonio before mutation.
- **Resolution:** Move, archive, and restore capture the exact server-read previous folder.
- **Regression/evidence:** Inverse input is constructed from tool result state, not UI input.

### BUG-018 - Undo bypassed normal write confirmation risk
- **Symptom:** A convenience action could have become an unconfirmed mutation route.
- **Root cause:** There was no dedicated two-step Undo boundary.
- **Resolution:** Undo now produces a preview and requires a fresh single-use confirmation.
- **Regression/evidence:** Direct execution without confirmation is rejected.

### BUG-019 - Database backups omitted local safety state
- **Symptom:** Restoring PostgreSQL could lose audit Undo data and emergency write state.
- **Root cause:** Backup tooling captured only the PostgreSQL database.
- **Resolution:** Added a consistent SQLite snapshot plus config and safety-state archive.
- **Regression/evidence:** Backup contracts require manifest, checksum, and runtime archive creation.

### BUG-020 - Backup archives were not verified automatically
- **Symptom:** A scheduled dump could exist but be unreadable.
- **Root cause:** Creation did not run a format verification step.
- **Resolution:** Backup policy runs `pg_restore --list` and writes SHA-256 records.
- **Regression/evidence:** Hardening tests require both verification operations.

### BUG-021 - Backup retention and offsite copy were manual
- **Symptom:** Local recovery storage could grow without bounds or remain single-copy.
- **Root cause:** No scheduled policy wrapper existed.
- **Resolution:** Added daily timer, bounded retention, and optional root-owned offsite directory.
- **Regression/evidence:** Policy validates retention and rejects root or relative offsite paths.

### BUG-022 - Restore procedures could target production during rehearsal
- **Symptom:** An operator typo could rehearse a restore against a live connection.
- **Root cause:** Drill and production connection identities were not compared.
- **Resolution:** The drill requires an isolated URL different from production and backup roles.
- **Regression/evidence:** Restore contract checks the isolation guard and matching runtime archive.

### BUG-023 - Gateway and worker lacked explicit resource ceilings
- **Symptom:** A runaway request or extraction workload could exhaust host resources.
- **Root cause:** Service units relied on system defaults.
- **Resolution:** Added memory, task, open-file, namespace, and system-call limits.
- **Regression/evidence:** Hardening tests inspect required unit limits.

### BUG-024 - Nginx open-file capacity was undocumented state
- **Symptom:** Connection growth could reach a service limit unrelated to application health.
- **Root cause:** The addon did not ship an explicit systemd drop-in.
- **Resolution:** Added a versioned Nginx limit drop-in applied only after maintenance restart.
- **Regression/evidence:** Installer packages the drop-in and avoids an automatic disruptive restart.

### BUG-025 - New operational UI text was incomplete across locales
- **Symptom:** Health, fallback, incremental sync, safety, and Undo labels fell back inconsistently.
- **Root cause:** New feature strings were added before all official catalogs were updated.
- **Resolution:** Added complete keys for English, French, Hindi, Indonesian, Italian, Portuguese,
  Russian, Spanish, and Thai.
- **Regression/evidence:** Locale parity reports 257 keys with placeholder validation.

### BUG-026 - Negative read-only instructions could be mistaken for a mailbox mutation
- **Symptom:** The UAT request `message IDs only; do not mark anything as read` attempted
  `get_email` with the invalid item ID `s` instead of listing unread messages.
- **Root cause:** The mutation classifier matched `mark ... read` inside a negative clause, and
  the exact-target parser accepted `ID` as a prefix of plural `IDs`.
- **Resolution:** Explicit read-only or leading mutation-denial clauses now block every mutation
  classifier, while an affirmative mutation preceding a narrow safety clause remains valid.
  Exact mail IDs now require a complete `ID` token. Unread-mail intent takes priority and list
  commands for folders or tags require an adjacent phrase instead of matching across a sentence.
- **Regression/evidence:** Intent and mutation-target suites cover the production prompt and the
  existing `mark this message; do not change other messages` safety pattern.

### BUG-027 - Restricted restore drill could not recreate the vector extension
- **Symptom:** The first isolated target rehearsal stopped before restoring RAG chunks with
  `permission denied to create extension vector`.
- **Root cause:** The archive correctly recorded the extension dependency, but the drill attempted
  extension ownership operations through the intentionally non-superuser addon role.
- **Resolution:** The drill now requires administrators to preinstall `vector` in the isolated
  database and excludes its extension entries from the restore list. The addon role remains
  non-superuser.
- **Regression/evidence:** Hardening contracts require the prerequisite check, filtered restore
  list, and absence of any role privilege escalation.

### BUG-028 - Explicit mail-count bounds were ignored
- **Symptom:** A request such as `List at most 2 unread emails` routed with a limit of 10, while
  summary requests could retrieve five full message bodies regardless of the user's smaller bound.
- **Root cause:** Read routing used fixed default limits and did not parse an explicit bounded count.
- **Resolution:** Added English and Indonesian count extraction with a hard maximum of 20 and
  applied the result to list, search, and full-body summary retrieval.
- **Regression/evidence:** Tool-routing tests verify 2, 3, and 4 item requests, the hard maximum,
  and the original read-only production prompt.

### BUG-029 - Plural object identifiers could become mutation targets
- **Symptom:** Phrases such as `Delete folder IDs only` selected a destructive tool with `IDs` as
  the target, and a plural folder move could degrade to the target `s`.
- **Root cause:** Exact organization target parsing accepted the plural token as an identifier and
  the move parser searched the complete phrase without isolating source and destination clauses.
- **Resolution:** Exact IDs now require a complete singular `ID` token or a direct non-ID value.
  Folder moves parse source and destination clauses independently and ambiguous prompts fail closed.
- **Regression/evidence:** Organization intent tests reject plural folder delete, tag delete, and
  folder move prompts while preserving valid exact-ID actions.

### BUG-030 - Transport failures ignored the active Carbonio language
- **Symptom:** Invalid JSON, missing proxy, non-JSON, and empty gateway responses displayed
  Indonesian text for users in every locale.
- **Root cause:** The shared response parser embedded Indonesian literals instead of translation keys.
- **Resolution:** Moved all four transport failures to the Carbonio i18n runtime and supplied
  English, French, Hindi, Indonesian, Italian, Portuguese, Russian, Spanish, and Thai messages.
- **Regression/evidence:** UI contracts require the translation runtime, and locale parity validates
  279 keys plus placeholder consistency across all nine catalogs.

### BUG-031 - PDF upload failure feedback appeared off-screen
- **Symptom:** Selecting a PDF and pressing Upload and index appeared to do nothing.
- **Root cause:** The fail-closed extractor error was written to the global page notice above the
  Organization Knowledge section.
- **Resolution:** Added a local live status region and a preflight explanation for unavailable
  PDF and Office extraction.
- **Regression/evidence:** The admin UI contract verifies the local notice and explicit extraction
  prerequisite message.

### BUG-032 - Pilot access required environment-file edits and a restart
- **Symptom:** Administrators could not see Carbonio users or enable AI for an account from the UI.
- **Root cause:** Access was evaluated only from process-start environment allowlists.
- **Resolution:** Added Admin SOAP account discovery, searchable checkboxes, protected atomic
  per-account overrides, live enforcement, and audit records.
- **Regression/evidence:** Security tests cover bootstrap compatibility, managed enable and disable,
  write dependency, file permissions, and invalid-target rejection. Production UAT covers actual
  Carbonio directory enumeration and policy persistence.

### BUG-033 - User search sent an invalid Carbonio directory filter
- **Symptom:** The initial account list loaded, but searching for a mailbox name returned an invalid
  search-filter SOAP error.
- **Root cause:** SearchDirectory expects a valid LDAP filter and cannot accept an unstructured term.
- **Resolution:** Added bounded LDAP escaping and a fixed OR filter across mail, UID, and display name.
- **Regression/evidence:** Unit tests cover normal terms and LDAP metacharacter injection, and live
  Admin Console UAT verifies a real Carbonio mailbox search.

### BUG-034 - Account revalidation rejected a valid Carbonio mailbox
- **Symptom:** A discovered active account could be selected, but saving returned that the account
  was not eligible for AI access.
- **Root cause:** The revalidation normalizer expected one `GetAccount` response shape and did not
  accept a nested account object or an immutable ID returned as an account attribute.
- **Resolution:** Normalized both response variants while preserving exact-ID revalidation and
  internal-account exclusion.
- **Regression/evidence:** Unit coverage verifies attribute-provided IDs. Live UAT verifies save,
  immediate enforcement, protected persistence, and restoration against a real account.

## Known limitations and open gates

1. Files and Docs plus Chats and rooms remain compatibility-gated on the tested Carbonio server.
2. Five Tasks mutations remain disabled because the server rejects documented task commands.
3. Document extraction is disabled by default and has no bundled third-party sandbox or parser.
4. In-memory metrics reset on gateway restart. Prometheus provides durable time-series storage.
5. Provider failover improves availability but does not guarantee equivalent model behavior.
6. Undo is limited to mapped reversible actions and does not cover sending or permanent deletion.
7. Site-specific RAG quality, capacity, PostgreSQL HA, and recovery objectives remain external gates.
8. Authenticated multi-browser and Carbonio upgrade rehearsal remain target-environment gates.
9. `openrouter/free` can temporarily have no endpoint compatible with enforced Zero Data
   Retention. This testing-only availability failure does not weaken the production privacy lock.
10. The Mail menu compatibility bridge depends on the tested Carbonio `data-testid` contract.
    A Mail UI upgrade can hide `Ask AI` until compatibility is revalidated. Core Mail actions are
    not replaced and remain available when the bridge fails closed.
11. Carbonio Admin Console v0.15.2 has no public addon registry. Its dedicated AI page is reached
    by direct route or the administrator link in Webmail Settings. Carbonio Nginx template changes
    must be revalidated during an Admin Console or Proxy upgrade.

## Deferred scope
