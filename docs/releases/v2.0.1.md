# Carbonio AI Assistant v2.0.1

**Release class:** GitHub full release for user-scoped Carbonio deployments

**Release date:** 2026-08-08

**License:** MIT

**Required runtime:** Node.js v22.22.0 for the packaged gateway

## Executive summary

Version `2.0.1` retains the production user-only private RAG architecture introduced in
`v2.0.0` and fixes Mail and attachment synchronization on Carbonio servers that interpret
the unsupported pseudo-folder query `in:anywhere` as the literal folder path `//anywhere`.
All-mail indexing now omits the optional Search query, as allowed by the official Carbonio
Search contract. Attachment indexing uses only `has:attachment`. The patch includes a pure
request-builder regression that rejects any return of the invalid pseudo-folder scope.
The Settings source card now polls only while a source is synchronizing and stops once the
source becomes ready or fails, so users no longer need to reload the page to see final counts.
Tasks synchronization also handles servers that reject `types=task`. It retries the same
user-scoped search against appointment-backed items in standard Tasks folder ID 15 and reads
every result through the official authenticated `GetTask` operation.

The underlying `v2.0.0` release provides the first production user-only private RAG architecture for the
supported Carbonio Mail APIs. Users explicitly enable and synchronize Mail, safe attachment
text and metadata, Calendar, Tasks, or personal Contacts from localized Settings. Private
text and durable jobs are encrypted. PostgreSQL forced RLS isolates owners, GIN and pgvector
provide hybrid retrieval, and a separate hardened worker processes jobs without receiving a
Carbonio session cookie. Every candidate record is revalidated live before provider use.
Deleted, revoked, stale, disabled, and forged-citation paths fail closed.

Carbonio AI Assistant is a standalone Carbonio Webmail microfrontend backed by a separate
Node.js AI gateway. It adds a ChatGPT-style workspace to Carbonio without modifying the
existing Mail module. The gateway binds to loopback and is exposed only through the
Carbonio Nginx route, where it verifies the active Carbonio session before using an AI
provider or a Carbonio SOAP tool.

Version `2.0.0` retains the complete beta.1 core product for controlled pilots and closes
a privacy-routing defect found during authenticated UAT. Instructions that explicitly deny
email or calendar access now bypass all Carbonio mailbox and calendar tools, documentation
RAG, and synthetic tool context; the provider receives exactly one original user message.
Conversation history remains in PostgreSQL, administrators manage providers and credentials,
users select an allowed model, and every email or calendar mutation remains protected by a
preview and one-time confirmation. Eight external acceptance gates that lack a complete
environment or evidence set were explicitly accepted as known limitations and remain tracked
after release.

The v1 model-consistency hotfix, safe plain-text answers, context-aware panel, confirmation
framework, PostgreSQL history, and all nine official locales remain included. Files/Docs and
Chats intentionally remain unavailable until official user-scoped compatibility probes pass.

## Context-aware side panel scope

- Uses Carbonio Shell `addUtilityView` rather than modifying the Mail or Calendar core.
- Appears only on allowlisted Mail, Calendar, and assistant routes.
- Detects message, conversation, and appointment references without reading DOM body content.
- Requires the user to enable `Use this selected item` before context actions become active.
- Re-fetches messages, threads, and appointments server-side through registered read tools.
- Supports email summary, action extraction, reply drafting, meeting preparation, and follow-up.
- Stores panel conversations in the same owner-isolated server-side history as full chat.
- Never executes a write confirmation inside the compact panel; write actions must be reviewed
  in the full assistant.
- Cancels in-flight work, clears context, and resets consent whenever the selected item changes.
- Localizes panel UI and interpolation tokens across `en`, `fr`, `hi`, `id`, `it`, `pt`, `ru`,
  `es`, and `th`.

## User-only private RAG scope

- User-owned opt-in controls for Mail, attachments, Calendar, Tasks, and personal Contacts.
- Files/Docs and Chats compatibility gates return an explicit unavailable state.
- GAL remains live-only and is never indexed.
- AES-256-GCM encrypted normalized text and job payloads with no persisted session cookie.
- Forced RLS and transaction-local owner context on sources, documents, chunks, and tombstones.
- GIN full-text search, 384-dimensional pgvector storage, HNSW cosine search, reciprocal-rank
  fusion, relevance thresholding, deduplication, and an eight-chunk context bound.
- A separate systemd worker with durable ordered jobs, retry/backoff, sync finalization,
  deletion tombstones, graceful shutdown, and structured text-free logs.
- Separate restricted worker and root-only `BYPASSRLS` backup roles so runtime RLS and complete
  disaster recovery do not weaken each other.
- Live exact-source and revision revalidation before provider use.
- Safe attachment text extraction for bounded text, CSV, Markdown, JSON, and XML only.
- Provider output validation that removes forged private citation references.

## v1.0.2 hotfix retained

- Settings now shows the effective provider and model returned by the gateway.
- Environment-managed provider, endpoint, and model fields are visibly locked and rejected
  server-side if a conflicting update is attempted.
- A deterministic configuration revision covers the effective route and model policies.
- A changed revision invalidates all stale saved account model preferences.
- Opening historical conversations no longer changes the model used by the next request.
- Assistant bubbles remove unsupported Markdown emphasis, headings, and horizontal rules.
- Labeled 13-digit timestamps are rendered with the active Carbonio locale.
- The provider prompt requests plain text so normalization is a safety net, not the primary

- Existing user messages and stored conversation records are not rewritten.

## User experience and UI

The addon registers a robot icon in Carbonio's primary navigation and owns an independent
assistant route. The route does not replace or patch the Mail application. It follows the
Carbonio theme, supports desktop and narrow panes, avoids a forced two-column layout at
small widths, and honors reduced-motion behavior.

The main assistant includes:

- a conversation list with active state, title search, cursor pagination, and localized
  loading/empty/error states;
- ChatGPT-style history row actions that appear on hover or keyboard focus;
- direct delete plus overflow actions, inline rename, soft-delete notification, and Undo;
- a per-conversation model selector constrained by administrator policy;
- localized suggested prompts, settings, status, confirmation, retry, stop, and send UI;
- streaming response rendering and process markers for documentation lookup, mailbox
  access, and provider generation;
- accessible native buttons and labels that remain visible under Carbonio Design System
  theme tokens;
- bounded action previews that show the exact email, recipients, destination, appointment,
  or before/after calendar changes before a mutation can run;
- safe text rendering, localized failure messages, and a visible request ID for support.

Conversation summaries expose metadata only. Full messages are fetched only when the user
opens a conversation. The browser does not own the durable history database.

## Provider and model configuration

The Settings experience provides presets so administrators do not need to type common
API endpoints manually. Implemented configuration paths cover OpenRouter, OpenAI,
Anthropic/Claude, DeepSeek, Gemini, and a custom OpenAI-compatible endpoint. A custom URL
must pass the configured endpoint allowlist; arbitrary endpoints fail closed.

Provider credentials are administrator-owned. API keys are not returned to the browser,
and the encrypted systemd credential helper migrates legacy plaintext settings only after
encryption succeeds. An empty `AI_ADMIN_ACCOUNTS` list grants no user administrator access.
Provider/model allowlists can be scoped by account, Carbonio group, or domain, while the
selected model remains an owner-scoped user preference rather than a global setting.

Model discovery and allowlisting are supported. OpenRouter free models can be used for a
low-cost pilot, but availability can change and must be rechecked at rollout. Production
OpenRouter requests enforce `data_collection=deny` and `zdr=true` in code even when an
environment override attempts to weaken those settings. Provider configuration paths are
implemented; this report does not claim that every third-party provider was live-tested.

## Conversation history and PostgreSQL

Production history is stored server-side in PostgreSQL and isolated by the authenticated
Carbonio account ID. The data model supports conversations, normalized messages,
owner-scoped preferences, message counts, soft deletion, daily input/output token usage,
and versioned migrations. Conversation APIs provide bounded cursor pagination, title
search, rename, delete, restore, and metadata-only lists.

Message content can be protected with AES-256-GCM when the deployment supplies the
history-encryption key. Production smoke checks fail closed unless health reports
`historyBackend: "postgresql"`; SQLite remains a local-development fallback only.

The pilot gateway survived a real PostgreSQL idle-backend termination and reconnected
through the same pool without changing the gateway process. The active pilot health result
reported `historyBackend: "postgresql"`, and strict smoke completed with:

```text
smoke_health=ok headers=ok loopback=ok admin_auth=ok csrf=ok history=postgresql
```

## Tool Framework and safety model

All mailbox and calendar operations run through a shared registry and runner. Each tool
declares an input schema, required permission scope, result limit, timeout, and risk level:
`READ`, `DRAFT`, `WRITE`, or `DESTRUCTIVE`. The runner validates inputs and policy before
calling Carbonio and emits owner-scoped structured audit records with request IDs and
bounded result references.

Mutations use a two-stage contract:

1. Resolve and revalidate the exact current target, then render a bounded preview.
2. Execute only after the authenticated owner accepts an account-bound, one-time
   confirmation token with an idempotency key.

Preview generation does not execute the mutation. The confirmation token is bound to the
owner, tool, and hash of the exact previewed input; replayed tokens do not create duplicate
mutations. Ambiguous or overly broad targets fail before preview, while appointment
`ms`/`rev` values provide action-time stale-version protection. Provider cancellation,
bounded tool and SOAP request timeouts, output-size limits, daily quotas,
account/group/domain permissions, and the global write-tool kill switch further bound
execution. Email mutations use the exact ID bound into the confirmation input but do not
perform a second `GetMsg` after the user confirms.

## Email capabilities

Implemented email tools and their boundaries are:

| Tool | Risk | Boundary |
| --- | --- | --- |
| `search_emails` | READ | Bounded metadata search; no full-body request for lists. |
| `list_unread_emails` | READ | Bounded unread listing; reading does not mark messages read. |
| `get_email` | READ | Exact message retrieval with safe HTML-to-text normalization. |
| `get_email_thread` | READ | Bounded `GetConv` thread retrieval and summarization input. |
| `list_attachments` | READ | Metadata only; attachment content is not uploaded automatically. |
| `create_email_draft` | DRAFT | Builds a reply/new draft preview and saves only after confirmation. |
| `update_email_draft` | DRAFT | Updates an exact draft target after preview. |
| `forward_as_draft` | DRAFT | Creates a forward draft; it never auto-sends. |
| `send_email` | WRITE | Previews To/CC/BCC/subject/body and sends once after confirmation. |
| `mark_as_read` | WRITE | Revalidates one exact message ID before `MsgAction`. |
| `add_tag` | WRITE | Revalidates the message and selected tag before mutation. |
| `move_email` | WRITE | Requires one unambiguous named destination and exact message. |
| `delete_email` | DESTRUCTIVE | Separate permanent-delete tool with destructive warning. |

The gateway uses Carbonio `Search`, `GetMsg`, `GetConv`, `SaveDraft`, `SendMsg`, and
`MsgAction` SOAP operations. Draft creation is intentionally distinct from send: no draft
flow silently sends a message. HTML is normalized to safe plain text, remote images are not
loaded by the tool, and list/search operations minimize mailbox content disclosure.

## Calendar, meeting, and contact capabilities

Implemented calendar/contact tools are:

- `search_appointments` and `get_appointment` for bounded lookup and exact details;
- `search_contacts` and `resolve_attendees` for contact/GAL attendee resolution;
- `check_free_busy` and `propose_meeting_slots` for timezone-aware conflict checking and
  up to three alternatives;
- `create_calendar_draft` for a non-sending meeting draft;
- `create_appointment` for confirmed creation;
- `update_appointment` for an exact version-aware before/after proposal;
- `send_meeting_invitation` for confirmed attendee invitation;
- `cancel_appointment` as a destructive confirmed action.

The gateway uses Carbonio `Search`, `GetAppointment`, `GetFreeBusy`,
`CreateAppointment`, `ModifyAppointment`, and `CancelAppointment` operations. Update
previews bind Carbonio `ms` and `rev` values and fail when the appointment changed.
Timezone conversion and attendee conflicts are shown before confirmation. Recurring event
mutations are rejected at natural-language routing, schema validation, and direct tool API
entry points rather than guessing which occurrence the user intended.

## Carbonio documentation knowledge MVP

v2.0.0 contains a curated lexical index covering official Carbonio email API guidance,
including bounded `GetMsg`, `SaveDraft`, `SendMsg`, reply/forward, and attachment patterns.
Retrieval is local, activates only for Carbonio API guidance or compose-related requests,
and returns source title, URL, and version metadata for citation rendering.

This is documentation grounding, not production mailbox/files RAG. It does not create
embeddings, use `pgvector`, import arbitrary user workspaces, or index users' mailboxes.

## Security, privacy, and administration

The production boundary includes:

- Carbonio-session verification and account-scoped ownership;
- CSRF/origin enforcement and Carbonio Nginx security headers;
- loopback-only gateway binding (`127.0.0.1`) behind the Carbonio proxy;
- account/group/domain allowlists for enablement, models, and tool scopes;
- administrator-only provider and credential controls;
- encrypted credential storage with no API-key echo to the browser;
- production PostgreSQL enforcement and optional encrypted history content;
- output sanitization, HTML-to-text normalization, bounded results, and data minimization;
- OpenRouter production privacy locks and disclosure copy for third-party processing;
- one-time confirmation, idempotency, exact-target checks, and destructive warnings;
- a write kill switch plus emergency addon disable path;
- daily request/token quotas and owner-scoped usage reporting;
- structured audit entries, administrator audit/status view, metrics, and provider health.

Operators must still use an external secret manager, restrict pilot identities, disable
provider training/logging where supported, and avoid confidential production messages
during free-model evaluation.

## Reliability and observability

The UI, gateway, provider calls, tool runner, and SOAP boundary share a request ID. JSON
logs redact known secret fields and record request status, tool name, duration, bounded
result references, and errors without including API keys. SSE errors preserve the same
request ID so users can correlate a visible failure with gateway logs.

Provider retry is restricted to transient network failures and HTTP `429`, `502`, and
`503`; invalid credentials are not retried. Requests have bounded timeouts, cancellation
propagates from the UI to the gateway/provider, and provider circuit breakers support
half-open recovery. The health endpoint reports operating mode and history backend, while
administrator metrics expose provider/tool health and quota usage.

PostgreSQL pool error listeners keep idle-client failures from terminating the process.
Regression coverage includes real PostgreSQL disconnect/reconnect behavior. Localized UI
errors avoid leaking secrets and retain the request ID.

## Complete closed-bug ledger

### BUG-001 — HTML error page parsed as JSON

- **Symptom:** the browser showed `Unexpected token '<'` when a login/proxy HTML page was
  returned where JSON was expected.
- **Root cause:** the client assumed every gateway response body was JSON without first
  validating status/content type.
- **Resolution:** gateway routing and client error handling distinguish HTTP/HTML failures
  from valid JSON/SSE responses and surface a localized gateway error.
- **Regression/evidence:** live proxy testing progressed from the parse failure to typed
  gateway responses and successful provider streaming.

### BUG-002 — Gateway route/method returned HTTP 405

- **Symptom:** the AI gateway returned `HTTP 405` after the UI was connected to Carbonio.
- **Root cause:** the browser method/path did not match the proxied gateway endpoint.
- **Resolution:** UI request routing, Nginx proxy path, and gateway method handling were
  aligned under `/api/ai/**`.
- **Regression/evidence:** strict loopback/proxy smoke and authenticated round-trip passed.

### BUG-003 — Successful stream did not render an answer

- **Symptom:** the request reached the agent but no assistant answer appeared.
- **Root cause:** the UI did not consistently consume/render provider SSE chunks and
  completion state.
- **Resolution:** a bounded SSE transport and stream state handler now append chunks,
  process tool events, handle completion, and surface failures.
- **Regression/evidence:** agent-stream UI contract and live provider answer rendering.

### BUG-004 — Browser-only conversation history disappeared

- **Symptom:** conversations were lost across browser/session state changes.
- **Root cause:** early history lived only in client state/local storage.
- **Resolution:** durable owner-scoped gateway persistence, then production PostgreSQL,
  replaced browser-owned history.
- **Regression/evidence:** history CRUD/isolation tests, reload checks, and PostgreSQL
  restart survival.

### BUG-005 — History actions/delete were invisible or inconsistent

- **Symptom:** Webmail users could not discover the requested delete/history controls.
- **Root cause:** action affordances depended on layout/theme behavior and were only
  available inconsistently through overflow UI.
- **Resolution:** direct delete plus overflow actions appear on hover/focus, with inline
  rename and soft-delete Undo.
- **Regression/evidence:** UI contract and authenticated Webmail observation.

### BUG-006 — Robot icon/layout broke inside Carbonio dimensions

- **Symptom:** icon alignment and assistant columns looked incorrect in the real Webmail
  shell despite working locally.
- **Root cause:** initial dimensions and colors assumed a standalone viewport rather than
  Carbonio navigation, pane widths, and theme tokens.
- **Resolution:** Carbonio-aware navigation sizing, native theme tokens, narrow-pane
  breakpoints, and a dedicated robot icon were added.
- **Regression/evidence:** responsive/theme contracts and live Webmail route inspection.

### BUG-007 — English/Indonesian strings diverged

- **Symptom:** controls and action states were incomplete or inconsistent between locales.
- **Root cause:** new UI/action strings were added without enforced catalog parity.
- **Resolution:** Carbonio locale integration and translation-parity contracts cover the
  assistant, settings, actions, status, accessibility, and errors.
- **Regression/evidence:** i18n parity self-test.

### BUG-008 — Common providers required manual endpoints

- **Symptom:** administrators had to know and type provider URLs for every configuration.
- **Root cause:** Settings originally exposed only a generic endpoint field.
- **Resolution:** provider presets supply known endpoints while a separately allowlisted
  custom OpenAI-compatible path remains available.
- **Regression/evidence:** provider settings and endpoint validation self-tests.

### BUG-009 — Credential exposure/misleading browser display

- **Symptom:** legacy settings could retain plaintext credentials or imply that a saved
  API key was retrievable in the browser.
- **Root cause:** early configuration ownership was mixed between browser-visible config
  and server runtime state.
- **Resolution:** administrator-owned encrypted systemd credentials, non-disclosure in
  API responses, and migration that deletes plaintext only after encryption succeeds.
- **Regression/evidence:** credential migration/security tests and redacted settings API.

### BUG-010 — SSE failures lost their request ID

- **Symptom:** users saw a stream error but could not correlate it with server logs.
- **Root cause:** the SSE error boundary discarded gateway request metadata.
- **Resolution:** request IDs propagate through streamed failures to localized UI errors.
- **Regression/evidence:** request-ID stream regression contract (`0.0.3-rc.14`).

### BUG-011 — Calendar search used an invalid broad scope

- **Symptom:** an otherwise empty appointment search did not reliably target the default
  Carbonio calendar.
- **Root cause:** the Carbonio search grammar required an explicit calendar folder scope.
- **Resolution:** upcoming searches add `inid:10` when no narrower query exists.
- **Regression/evidence:** calendar query regression and authenticated UAT (`rc.11`).

### BUG-012 — Live `GetAppointment` array shapes were rejected

- **Symptom:** real appointment responses failed normalization or lost before/after fields.
- **Root cause:** fixtures assumed scalar objects while Carbonio returned array-shaped
  start, end, organizer, and timezone fields.
- **Resolution:** normalization accepts both documented/live array forms.
- **Regression/evidence:** appointment-result self-test based on live shape (`rc.12`).

### BUG-013 — Recurring mutations were not rejected everywhere

- **Symptom:** a direct tool API path could bypass natural-language recurring-event guard.
- **Root cause:** rejection existed at routing but not at every schema/runner boundary.
- **Resolution:** recurring update/invite/cancel inputs fail at schema validation and direct
  tool execution as well as routing.
- **Regression/evidence:** gateway direct-tool regression (`rc.13`).

### BUG-014 — OpenRouter privacy depended on configuration

- **Symptom:** an environment override could disable intended ZDR/data-collection controls.
- **Root cause:** privacy parameters were defaults rather than production invariants.
- **Resolution:** production outbound requests always enforce ZDR and deny data collection.
- **Regression/evidence:** captured outbound provider-request test (`rc.15`).

### BUG-015 — PostgreSQL idle errors could destabilize gateway

- **Symptom:** terminating an idle database backend could emit an unhandled pool-client
  error and threaten gateway availability.
- **Root cause:** the pool lacked a safe idle-error listener/reconnect path.
- **Resolution:** errors are secret-safely logged, the process remains alive, and the next
  operation reconnects through the pool.
- **Regression/evidence:** real PostgreSQL idle termination/reconnect plus live PID check
  (`rc.16`).

### BUG-016 — Production smoke could accept SQLite

- **Symptom:** a nominally healthy deployment could silently use development SQLite.
- **Root cause:** smoke checked general health but not the declared history backend.
- **Resolution:** production smoke requires `historyBackend == "postgresql"`.
- **Regression/evidence:** fail-closed smoke contract and pilot strict-smoke output
  (`rc.17`).

### BUG-017 — Tag release lacked full branch gates

- **Symptom:** early tags could package without PostgreSQL/security parity with branch CI.
- **Root cause:** release and CI workflows had different gate sets.
- **Resolution:** tag workflow runs UI/deploy/gateway/PostgreSQL tests, audits, and secret
  scan before publication.
- **Regression/evidence:** release workflow contract and successful RC19 workflows.

### BUG-018 — Mutation targets could be ambiguous or stale

- **Symptom:** broad criteria or changed mailbox/calendar state could resolve a different
  object between request and confirmation.
- **Root cause:** target binding was not uniformly exact/version-aware.
- **Resolution:** explicit/latest/singular rules resolve the target before preview; the
  confirmation token binds the owner, tool, and exact input hash; appointment `ms`/`rev`
  values add action-time stale-version checks. Email confirmation remains bound to the
  previewed exact ID but does not issue a second `GetMsg`.
- **Regression/evidence:** mutation-target regression suite (`rc.17`).

### BUG-019 — Terminal punctuation became part of an item ID

- **Symptom:** `email ID 435.` reached Carbonio as malformed ID `435.`.
- **Root cause:** sentence punctuation was included by the explicit-ID parser.
- **Resolution:** only terminal sentence punctuation is removed before exact `GetMsg`
  revalidation.
- **Regression/evidence:** authenticated reproduction and parser test (`rc.18`).

### BUG-020 — Folder-qualified explicit IDs were rejected

- **Symptom:** `email Inbox ID 440` was treated as ambiguous instead of exact.
- **Root cause:** the parser did not recognize safe standard-folder qualifiers around an
  explicit ID.
- **Resolution:** known Carbonio folder qualifiers are accepted while the ID is still
  revalidated through exact `GetMsg`.
- **Regression/evidence:** parser regression and live Inbox ID 440 preview (`rc.19`).

### BUG-021 — Source folder could become move destination

- **Symptom:** `Inbox` in `email Inbox ID 440 ... Trash` could be selected as destination.
- **Root cause:** destination parsing scanned any folder word rather than the terminal
  destination clause.
- **Resolution:** move destination resolves only from one complete terminal destination
  clause in either supported UI language.
- **Regression/evidence:** parser test and live move-to-Trash preview/execution (`rc.19`).

### BUG-022 — Connector inside quoted subject confused destination

- **Symptom:** words such as `to` inside a quoted subject could alter move parsing.
- **Root cause:** connector scanning did not preserve quoted subject boundaries.
- **Resolution:** exact target parsing and terminal destination extraction keep quoted
  content separate.
- **Regression/evidence:** quoted-subject parser regression (`rc.19`).

### BUG-023 — Multiple move destinations silently selected one

- **Symptom:** a command such as `Inbox or Trash` could choose the first folder.
- **Root cause:** the parser accepted the first recognized destination instead of treating
  multiple candidates as ambiguous.
- **Resolution:** multiple destinations fail closed before mailbox access.
- **Regression/evidence:** ambiguity regression (`rc.19`).

### BUG-024 — Bare numeric folder destination broadened targeting

- **Symptom:** a numeric value could be interpreted as a destination folder without
  explicit semantics.
- **Root cause:** loose numeric folder parsing conflated identifiers and destinations.
- **Resolution:** move destinations require one complete, recognized named-folder clause;
  bare numeric values are rejected.
- **Regression/evidence:** fail-closed parser regression (`rc.19`).

### BUG-025 — Explicit data-access denial triggered mailbox search and documentation RAG

- **Symptom:** an authenticated beta.1 UAT prompt written in Indonesian explicitly denied
  email and calendar access, but still retrieved four Carbonio documentation chunks and
  searched the inbox because the negated sentence contained reply and email keywords. The
  model returned unrelated draft guidance instead of the requested exact phrase.
- **Root cause:** knowledge and mailbox routing used positive lexical matching without an
  earlier privacy-intent guard.
- **Resolution:** a clause-aware bilingual opt-out classifier now runs before knowledge,
  action, and tool selection. A context-free provider path sends exactly one original
  user message without system, mailbox, calendar, or RAG wrappers.
- **Regression/evidence:** 13 real `runAgent` → provider opt-out prompts and eight
  quoted/hypothetical/ordinary negative cases pass. Authenticated Chrome retest loaded
  exact asset commit `d3ea937e38d126a5f202bd2e9e9ccddfe62433ff`, returned only
  the requested beta activation phrase, and request
  `9cf82688-e4bf-40bf-b17d-d8901f4e8c2f` contained session
  `GetInfo`, provider HTTP 200, and chat HTTP 200 with no Search, agent tool,
  `knowledge_retrieved`, confirmation, or mutation.

### BUG-026 - Saved Settings model did not become the effective model

- **Symptom:** An administrator saved a new OpenRouter model, but subsequent answers still
  used the previously configured model.
- **Root cause:** `AI_AGENT_MODEL` had higher precedence than persisted runtime Settings and
  the API did not disclose that the model field was locked by the environment.
- **Resolution:** The public Settings contract now returns effective values, field sources,
  lock metadata, and a deterministic configuration revision. Conflicting writes to locked
  fields fail explicitly and the UI disables those fields with a managed-environment hint.
- **Regression/evidence:** Gateway security regression verifies locked model disclosure,
  conflicting-write rejection, runtime model activation, and revision change.

### BUG-027 - Historical conversation silently restored a retired model

- **Symptom:** Opening an older conversation could route the next request to the model saved
  on that conversation even after the administrator or user changed model configuration.
- **Root cause:** The conversation load handlers copied historical model metadata into the
  active request model state.
- **Resolution:** Conversation history keeps its model metadata for audit, but active request
  routing always follows the current allowed account preference and effective gateway model.
- **Regression/evidence:** TypeScript, UI contract, and model-selection source regressions
  pass with the historical assignment removed from initial and explicit conversation loads.

### BUG-028 - Stale account preferences survived a configuration revision

- **Symptom:** Existing account preferences could continue selecting an old model after a
  provider, endpoint, model, allowlist, or scoped model policy change.
- **Root cause:** Preferences had no relationship to an effective configuration revision.
- **Resolution:** The gateway computes a revision from effective routing and model policies.
  A successful Settings update that changes the revision purges stored model preferences so
  each account resolves a fresh valid default on its next request.
- **Regression/evidence:** SQLite and PostgreSQL adapters expose the same purge operation,
  while gateway regressions verify revision changes and allowlist enforcement.

### BUG-029 - Unsupported Markdown markers were shown literally in chat

- **Symptom:** Assistant responses displayed strings such as `###`, `**Unread**`, and
  raw 13-digit timestamps because chat bubbles intentionally do not render arbitrary HTML.
- **Root cause:** The provider was allowed to produce Markdown while the safe text-only UI
  rendered the response literally.
- **Resolution:** Provider guidance now requests plain text. Assistant display normalization
  removes headings, emphasis markers, and horizontal rules, and formats labeled millisecond
  timestamps with the active locale without enabling unsafe HTML rendering.
- **Regression/evidence:** A golden regression covers the reported TEST UPGRADE response,
  localized timestamp conversion, safe rendering, i18n, lint, and TypeScript.

### BUG-030 - Newly disclosed build dependency advisories failed the release gate

- **Symptom:** Dependency audit identified high-severity legacy build-chain findings and later
  disclosed moderate PostCSS path-disclosure and DOMPurify detached-subtree findings.
- **Root cause:** The Carbonio UI SDK and Shell dependency graph resolved transitive versions
  published before the upstream security fixes.
- **Resolution:** Workspace overrides pin patched compatible releases and upgrade Less to a
  release that no longer depends on image-size. PostCSS is pinned to `8.5.23` and DOMPurify to
  `3.4.13`. These are build-time dependencies and are not added to the packaged gateway runtime.
- **Regression/evidence:** `pnpm audit --audit-level moderate` reports no known finding,
  followed by a clean install, lint, type-check, UI tests, gateway tests, build, and package.

### BUG-031 - Private source data could be mixed without database owner enforcement

- **Symptom:** An application-only owner filter would make a future missing predicate capable
  of exposing another user's indexed chunk.
- **Root cause:** The v1 history schema did not include a private retrieval store or forced RLS.
- **Resolution:** Sources, documents, chunks, and tombstones use forced RLS with a transaction-local
  authenticated owner ID plus explicit owner predicates.
- **Regression/evidence:** The database regression creates two unique owners and proves owner A
  cannot retrieve owner B's unique evidence token.

### BUG-032 - Source removal could leave retrievable vectors

- **Symptom:** Turning indexing off could leave old chunks visible until a background cleanup.
- **Root cause:** Retrieval blocking and physical deletion were separate conceptual operations.
- **Resolution:** Disable, retrieval-state update, pending-job deletion, and document cascade
  execute in one owner-scoped transaction.
- **Regression/evidence:** Retrieval returns no result immediately after source disable.

### BUG-033 - Deleted Carbonio records could survive a later sync

- **Symptom:** Upserting current records alone would retain objects no longer returned by Carbonio.
- **Root cause:** Sync had no ordered finalization or deletion propagation.
- **Resolution:** Every sync ends with an ordered finalize job that tombstones missing IDs and
  deletes their documents and chunks.
- **Regression/evidence:** Queue and tombstone contract tests cover finalization and source counts.

### BUG-034 - Revoked or stale records could reach the provider

- **Symptom:** A record could change or become inaccessible after it was indexed.
- **Root cause:** Vector evidence alone cannot prove current Carbonio authorization or revision.
- **Resolution:** Every selected Mail, attachment parent, appointment, task, or contact is read or
  version-checked live through the user's active session before provider use.
- **Regression/evidence:** Missing, rejected, and revision-mismatched objects are filtered fail-closed.

### BUG-035 - Carbonio session cookies could be persisted in worker jobs

- **Symptom:** A naive background connector would need a long-lived mailbox credential.
- **Root cause:** A worker performing Carbonio collection would require session persistence.
- **Resolution:** Collection occurs synchronously in the authenticated gateway. Only encrypted
  normalized documents enter jobs, and the worker has no Carbonio read path.
- **Regression/evidence:** The job schema contract rejects cookie fields and documentation records
  the capability boundary.

### BUG-036 - Retrieved prompt injection could be treated as model instruction

- **Symptom:** An email or attachment could contain text asking the model to reveal data or call tools.
- **Root cause:** Untrusted retrieval content was not previously a private prompt channel.
- **Resolution:** Chunks are flagged for suspicious instruction patterns and wrapped as untrusted
  evidence under a system rule that forbids following embedded commands.
- **Regression/evidence:** Injection fixtures flag hostile text while RAG remains unable to execute writes.

### BUG-037 - Model output could invent private citations

- **Symptom:** A provider could return `[R99]` even when no such evidence was retrieved.
- **Root cause:** Citation identifiers were free-form model output.
- **Resolution:** The gateway permits only `[R#]` values present in the current retrieved set and
  appends the authoritative source list itself.
- **Regression/evidence:** Invalid private references are removed before the streamed answer is displayed.

### BUG-038 - Attachment extraction could process unsafe or oversized content

- **Symptom:** Arbitrary attachment parsing could expose the host to malformed binaries or malware.
- **Root cause:** Metadata-only v1 had no reviewed content extraction boundary.
- **Resolution:** v2 accepts only bounded text MIME types, checks returned MIME, rejects NUL/binary
  content, quarantines the EICAR signature, follows no redirects, and indexes other types as metadata.
- **Regression/evidence:** Source and security contracts cover allowlists, size caps, and fail-closed states.

### BUG-039 - A failed embedding service could corrupt vector shape

- **Symptom:** Non-finite or wrong-sized vectors could break search or poison ranking.
- **Root cause:** External embedding responses need strict validation and endpoint controls.
- **Resolution:** Only allowlisted self-hosted hosts are accepted and every response must contain exactly
  384 finite values. A local private vector keeps the gateway independent of worker/provider failure.
- **Regression/evidence:** The embedding contract asserts dimensions and host restrictions.

### BUG-040 - RAG work could overload or crash the chat gateway

- **Symptom:** Chunking, embedding retries, and indexing in the gateway would degrade user chat.
- **Root cause:** Retrieval ingestion and interactive requests have different resource profiles.
- **Resolution:** A separate hardened worker uses bounded jobs, retry/backoff, checkpoints through
  durable rows, graceful shutdown, and a 2,000-document safety cap.
- **Regression/evidence:** Packaging, systemd, smoke, queue, retry, and gateway-availability checks
  cover the separate service boundary.

### BUG-041 - Forced RLS blocked complete PostgreSQL backups

- **Symptom:** The predeployment backup failed when `pg_dump` reached a forced-RLS RAG table.
- **Root cause:** The legacy helper connected as the gateway table owner, and forced RLS correctly
  refuses an unscoped export even for that owner.
- **Resolution:** Setup creates a separate `carbonio_ai_backup` login with `BYPASSRLS`, membership
  needed for restore ownership operations, and a root-only connection URL. Application services
  never load this credential. Backup and restore prefer that URL. Restore excludes extension
  comments because the restricted role must not own or alter pgvector and pg_trgm extensions.
- **Regression/evidence:** A full post-migration production dump and `pg_restore --list` catalog
  validation are mandatory before candidate installation, followed by restore rehearsal on a
  disposable database.

### BUG-042 - Mail RAG synchronization used a nonexistent pseudo-folder

- **Symptom:** Enabling or synchronizing Mail and attachment sources returned `Carbonio SOAP
  error: no such folder path: //anywhere`; document and chunk counts remained zero.
- **Root cause:** The index collector sent `in:anywhere`, which this Carbonio server parsed as a
  literal folder named `anywhere` instead of an all-mail search scope.
- **Resolution:** All-mail indexing omits the optional Search query. Attachment indexing sends
  only the supported `has:attachment` predicate. Message typing, limits, sorting, and pagination
  remain explicit request fields.
- **Regression/evidence:** Request-builder tests prove that an empty all-mail search contains no
  query field, attachment search trims to `has:attachment`, and no generated payload contains
  `anywhere`. Full gateway regression passes. Settings contract coverage verifies bounded
  status polling while synchronization is active.

### BUG-043 - Tasks synchronization used a rejected Search item type

- **Symptom:** Tasks source synchronization returned `Carbonio SOAP error: invalid item type:
  task` and did not enqueue any task documents.
- **Root cause:** The generic official Search contract lists `task`, but this Carbonio server
  exposes tasks as appointment-backed items and rejects that Search type at runtime.
- **Resolution:** The collector first attempts the documented task type. Only for the exact
  incompatible-type response, it retries `types=appointment` within standard Tasks folder ID
  15, then retrieves each exact result through the official user-authenticated `GetTask`
  operation. Other SOAP errors remain fail-visible and are not swallowed.
- **Regression/evidence:** Request-builder fixtures cover both documented and compatibility
  modes, the stable folder ID query, and normalized `GetTask` content. Full gateway regression
  must pass before publication.

## Installation, upgrade, rollback, and verification

Use an approved maintenance window and run these operations as the Carbonio operator.
Never paste credentials into shell history or the release report.

### Before installation or upgrade

1. Confirm the public tag points to the reviewed commit and GitHub marks it as a pre-release.
2. Download the archive and checksum into a dedicated staging directory.
3. Validate the checksum:

   ```bash
   sha256sum -c carbonio-ai-assistant-v2.0.0.tar.gz.sha256
   ```

4. Create a PostgreSQL backup with the installed helper and validate its catalog:

   ```bash
   sudo /opt/carbonio-ai-assistant/bin/backup-postgres.sh
   sudo pg_restore --list /path/to/the/newly-created-backup.dump
   ```

5. Record the current UI/gateway symlink targets and service state.

### Install or upgrade

Extract the verified archive, enter its directory, inspect `release.env`, then run:

```bash
sudo ./install.sh
sudo /opt/carbonio-ai-assistant/bin/setup-rag-postgres.sh
sudo /opt/carbonio-ai-assistant/bin/smoke-test.sh
systemctl status carbonio-ai-gateway.service --no-pager
systemctl status carbonio-ai-rag-worker.service --no-pager
```

Expected strict smoke output ends with:

```text
smoke_health=ok headers=ok loopback=ok admin_auth=ok csrf=ok history=postgresql rag_worker=ok
```

Reload Carbonio Webmail with a hard refresh and verify the robot route, provider status,
one existing conversation, and one non-mutating mail query. Do not repeat mail/calendar
mutations without separate action-time approval.

### Rollback

Choose the previously recorded commit and run:

```bash
sudo /opt/carbonio-ai-assistant/bin/rollback.sh <previous-commit> --yes
sudo /opt/carbonio-ai-assistant/bin/smoke-test.sh
```

Rollback switches the versioned application release; it does not reverse database
migrations. Database restore is a separate emergency action requiring a verified backup
and explicit maintenance approval.

### Uninstall

Use the packaged uninstaller only after confirming retention/export requirements for
history, audit, and configuration data:

```bash
sudo ./uninstall.sh
```

After any install, upgrade, rollback, or uninstall, record the exact commit, archive
SHA-256, backup path, operator, smoke output, service status, and browser evidence.
