# Carbonio AI Assistant v2.3.1

**Release class:** Security hardening patch release

**Release date:** 2026-08-09

**License:** MIT

**Support status:** Independent community addon. Not developed, certified, endorsed, or supported by Zextras.

## Executive summary

Version 2.3.1 closes every actionable application and supply-chain finding from the post-v2.3.0
security audit. Administrator-managed AI disable policy now covers conversation history as well as
chat, tools, RAG, preferences, and configuration. Request and upstream response limits are enforced
while data is streaming. Remote Carbonio SOAP endpoints verify TLS by default. Public health output
no longer exposes database error text, worker details, or capacity information.

The release also narrows proxy trust boundaries, pins workflow dependencies and the PostgreSQL CI
image to immutable digests, and adds CodeQL plus dependency review. Repository settings that cannot
be represented in source are verified separately during release administration.

## Risk acceptance

- This remains an independent community addon and is not an official Zextras component.
- Operators own provider review, privacy policy, incident response, backups, monitoring, and upgrades.
- AI output remains probabilistic and every write or destructive preview must be reviewed.
- The loopback Carbonio SOAP default accepts the local certificate. Remote endpoints verify TLS.
- Setting `CARBONIO_ALLOW_INSECURE_REMOTE_TLS=true` deliberately accepts interception risk.
- Per-process API rate limiting is not a distributed denial-of-service control.
- A compromised Carbonio session retains the same mailbox authority as the authenticated user.

## Complete closed-bug ledger

### BUG-001 - Disabled users retained history API access
- **Symptom:** A disabled account could call conversation endpoints directly.
- **Root cause:** History routes resolved a session without applying AI access policy.
- **Resolution:** Every history operation now uses the common policy-enforcing authenticator.
- **Regression/evidence:** Security contracts require policy enforcement on the history routes.

### BUG-002 - History requests had no dedicated API rate limit
- **Symptom:** An authenticated account could repeatedly query or mutate its history.
- **Root cause:** Only AI generation requests consumed a minute quota.
- **Resolution:** Added a separate per-account API minute limiter for conversation operations.
- **Regression/evidence:** Security policy output exposes the configured bounded API limit.

### BUG-003 - Oversized request bodies were checked after buffering
- **Symptom:** A loopback client could force the gateway to retain an excessive body.
- **Root cause:** The size check ran only after the request stream ended.
- **Resolution:** Content length and accumulated bytes are checked before retaining each chunk.
- **Regression/evidence:** Tests reject declared and streamed overflow with status 413 semantics.

### BUG-004 - Provider success responses were unbounded
- **Symptom:** A provider could return a response large enough to pressure gateway memory.
- **Root cause:** The provider body used the unbounded response JSON helper.
- **Resolution:** Provider responses now use a configurable capped streaming reader.
- **Regression/evidence:** Oversized response fixtures fail before JSON parsing.

### BUG-005 - Provider error responses were unbounded
- **Symptom:** A failing provider could return an arbitrarily large diagnostic body.
- **Root cause:** Error handling read the complete response before slicing its message.
- **Resolution:** Error bodies are capped at 256 KB while streaming.
- **Regression/evidence:** The shared bounded reader covers success and error paths.

### BUG-006 - Model catalog responses were unbounded
- **Symptom:** A compromised model catalog could exhaust gateway memory.
- **Root cause:** Model discovery used unbounded JSON parsing.
- **Resolution:** Model catalog responses are capped at 4 MB.
- **Regression/evidence:** Model discovery imports the shared bounded JSON reader.

### BUG-007 - Embedding responses were unbounded
- **Symptom:** An allowlisted embedding endpoint could return an oversized payload.
- **Root cause:** Vector validation occurred only after unbounded JSON parsing.
- **Resolution:** Embedding responses are capped at 256 KB before dimension validation.
- **Regression/evidence:** Exactly 384 finite dimensions are still required after the byte check.

### BUG-008 - SOAP responses were accumulated without a cap
- **Symptom:** A faulty Carbonio endpoint could return excessive JSON.
- **Root cause:** SOAP response chunks were retained until connection close.
- **Resolution:** SOAP responses are destroyed after the configured byte ceiling is crossed.
- **Regression/evidence:** Mailbox regressions cover the bounded SOAP path.

### BUG-009 - Remote SOAP endpoints disabled TLS verification
- **Symptom:** Cookies sent to a remote SOAP URL lacked certificate verification.
- **Root cause:** `rejectUnauthorized` was always false.
- **Resolution:** Remote SOAP hosts verify certificates by default.
- **Regression/evidence:** Loopback and remote policy branches are documented and reviewed.

### BUG-010 - Insecure remote SOAP use was implicit
- **Symptom:** Local compatibility and remote TLS risk shared one behavior.
- **Root cause:** One TLS setting applied to every endpoint.
- **Resolution:** Remote insecure TLS now requires an explicit environment override.
- **Regression/evidence:** The example environment keeps the risk switch disabled.

### BUG-011 - Public health returned raw database errors
- **Symptom:** Unauthenticated health callers could receive internal failure text.
- **Root cause:** The caught exception message was included directly in JSON.
- **Resolution:** Public failures return a stable error state without internal text.
- **Regression/evidence:** The public catch path contains no error-message field.

### BUG-012 - Public health returned worker details
- **Symptom:** Worker runtime details were exposed without administrator authentication.
- **Root cause:** The complete RAG status object was forwarded publicly.
- **Resolution:** Public health now uses an explicit minimal projection.
- **Regression/evidence:** Detailed data remains behind authenticated administrator routes.

### BUG-013 - Public health returned storage capacity
- **Symptom:** Unauthenticated callers could infer RAG database size.
- **Root cause:** Capacity metadata was part of raw RAG status.
- **Resolution:** Capacity is omitted from the public projection.
- **Regression/evidence:** Public response construction lists every allowed field.

### BUG-014 - Public proxy preserved a client admin marker
- **Symptom:** The internal Admin Console marker was not cleared on Webmail traffic.
- **Root cause:** Nginx forwarded unspecified incoming headers.
- **Resolution:** The public proxy removes `X-Carbonio-AI-Admin-Console`.
- **Regression/evidence:** Hardening tests require the clearing directive.

### BUG-015 - Public proxy did not normalize forwarded host
- **Symptom:** Origin validation could observe a client-supplied forwarded host.
- **Root cause:** The public location set `Host` but not `X-Forwarded-Host`.
- **Resolution:** Nginx overwrites forwarded host with the received HTTP host.
- **Regression/evidence:** Hardening tests require the normalized directive.

### BUG-016 - Workflow actions used mutable tags
- **Symptom:** Tag movement could change CI code without a repository diff.
- **Root cause:** Actions were referenced by major or release tags.
- **Resolution:** Every action is pinned to an immutable commit SHA.
- **Regression/evidence:** CI, release, deploy, and security workflows use exact SHAs.

### BUG-017 - PostgreSQL CI image used a mutable tag
- **Symptom:** The test database could change between identical commits.
- **Root cause:** Workflows referenced only `postgres:16`.
- **Resolution:** The OCI image index is pinned to an immutable digest.
- **Regression/evidence:** CI and release workflows use the same digest.

### BUG-018 - Repository had no CodeQL workflow
- **Symptom:** GitHub reported no code-scanning analysis.
- **Root cause:** No CodeQL workflow was configured.
- **Resolution:** Added JavaScript and TypeScript analysis for pushes, pull requests, and weekly runs.
- **Regression/evidence:** The workflow uses minimal permissions and immutable actions.

### BUG-019 - Pull requests lacked dependency review
- **Symptom:** A vulnerable dependency could enter without a focused diff gate.
- **Root cause:** No pull-request dependency review existed.
- **Resolution:** Added a job rejecting moderate or higher severity additions.
- **Regression/evidence:** The action is immutable and has read-only contents permission.

### BUG-020 - API rate configuration was invisible
- **Symptom:** Operators could not confirm the non-generation request ceiling.
- **Root cause:** Policy output reported only the generation quota.
- **Resolution:** Added `apiRequestsPerMinute` to administrator-visible policy output.
- **Regression/evidence:** The value is clamped between 10 and 20,000.

### BUG-021 - Provider response limits were not configurable
- **Symptom:** Operators could not lower the provider ceiling on constrained servers.
- **Root cause:** No provider response byte setting existed.
- **Resolution:** Added `AI_PROVIDER_MAX_RESPONSE_BYTES`.
- **Regression/evidence:** It defaults to 2 MB and is capped at 10 MB.

### BUG-022 - SOAP response limits were undocumented
- **Symptom:** Operators could not reason about SOAP memory bounds.
- **Root cause:** SOAP had no explicit response ceiling.
- **Resolution:** Added `CARBONIO_SOAP_MAX_RESPONSE_BYTES` documentation.
- **Regression/evidence:** It defaults to 10 MB with a 50 MB ceiling.

### BUG-023 - Proxy trust boundaries were not explicit
- **Symptom:** Routing intent depended partly on inherited headers.
- **Root cause:** Only the administrator route set an internal marker.
- **Resolution:** Public traffic clears the marker while administrator traffic sets it.
- **Regression/evidence:** Both managed Nginx routes define the boundary.

### BUG-024 - Tests missed stream overflow behavior
- **Symptom:** Buffer-after-read behavior could return undetected.
- **Root cause:** Tests checked limits but not byte-stream enforcement.
- **Resolution:** Added declared-length, chunk-overflow, valid JSON, and oversized response fixtures.
- **Regression/evidence:** The hardening suite reports request and response bounds.

### BUG-025 - Audit closures lacked release metadata
- **Symptom:** Operators lacked an exact patch-level security record.
- **Root cause:** v2.3.0 predated the post-release code audit.
- **Resolution:** Added this report, changelog, environment documentation, and README updates.
- **Regression/evidence:** Release contracts require the v2.3.1 report and public links.

### BUG-026 - Provider inference trusted hostname substrings
- **Symptom:** A crafted URL containing an official hostname in its path or parent hostname could be
  classified as a built-in provider.
- **Root cause:** Startup provider inference used string `includes` checks on the complete URL.
- **Resolution:** Provider inference parses the URL and requires an exact normalized hostname.
- **Regression/evidence:** Tests reject path and suffix impersonation while accepting the exact host.

### BUG-027 - HTML entity normalization could decode twice
- **Symptom:** Nested entities such as `&amp;lt;` could become a literal less-than character.
- **Root cause:** Sequential entity replacements allowed output from one pass into a later pass.
- **Resolution:** Entity decoding now uses one bounded replacement pass.
- **Regression/evidence:** Nested entity fixtures remain encoded after one normalization pass.

### BUG-028 - Initial CodeQL analysis reported High alerts
- **Symptom:** The first security scan reported provider URL, entity decoding, and citation-test alerts.
- **Root cause:** CodeQL had not previously been part of the repository gate.
- **Resolution:** Fixed the runtime findings and rewrote citation assertions using parsed exact hosts.
- **Regression/evidence:** Release requires a second exact-commit CodeQL run with zero open alerts.

## Known limitations and open gates

- Repository protection and GitHub security feature activation require repository settings authority.
- The Nginx open-file warning requires an approved Carbonio Nginx maintenance restart.
- Rate limiting is process-local. Multi-node deployments need a shared edge limiter.
- Optional PDF and Office extraction remains disabled until its fail-closed toolchain exists.
- Files and Docs plus Chats and rooms remain unavailable on the tested Carbonio server APIs.

## Deferred scope

- Distributed rate limiting and multi-node high availability.
- Hardware-backed or external key management.
- Native Carbonio extension points if Zextras publishes supported APIs.

## Installation, upgrade, rollback, and verification

```bash
sha256sum --check carbonio-ai-assistant-v2.3.1.tar.gz.sha256
tar -xzf carbonio-ai-assistant-v2.3.1.tar.gz
cd carbonio-ai-assistant-v2.3.1
sudo ./install.sh
sudo /opt/carbonio-ai-assistant/bin/smoke-test.sh
```

The installer preserves configuration and data, creates a versioned release, updates symlinks
atomically, validates Nginx, and restarts addon services. Roll back with the previous commit:

```bash
sudo /opt/carbonio-ai-assistant/bin/rollback.sh <previous-commit>
sudo /opt/carbonio-ai-assistant/bin/smoke-test.sh
```

Uninstall remains available through `uninstall.sh`. Data is retained unless the operator explicitly
chooses the destructive data-removal option.
